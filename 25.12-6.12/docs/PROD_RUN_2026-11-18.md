## 3. 本轮修好的问题

### 3.1 WAN eth1 无收包（0037）

`nsscc` 的 `nss_cc_parent_data_0` 索引 4..9 指向 UNIPHY0/1/2 的 NSS RX/TX 时钟，
这些时钟由主线 PCS 驱动注册。板级 DTS 把 `pcs0/1/2` 全 disabled 且内核未开
`CONFIG_PCS_QCOM_IPQ9574`，父时钟解析全 NULL，`__clk_rcg2_select_conf` 每次
determine_rate 都 WARN，port5（WAN）时钟设不上 → RX 恒 0。

修复：`CONFIG_PCS_QCOM_IPQ9574=y` + `&pcs0/1/2 { status = "okay"; }`（补丁 0037）。
CCF 父时钟懒解析且不缓存失败，与 nsscc 的 probe 顺序无关；qca-ssdk 用裸 ioremap
访问同一 UNIPHY 块，与 PCS 驱动的 `devm_platform_ioremap_resource` 不冲突。

### 3.2 MDIO 扫描丢 0x10–0x13/0x1c（0150，真机 v3 已验证）

上游 6.12 mdio-ipq4019 不脉冲整条 `phy-reset-gpio` 数组。补丁 0150 在 probe 时
`devm_gpiod_get_array_optional(..., "phy-reset", GPIOD_OUT_LOW)`，扫描前整数组
100 ms 拉低 + 1 s 静置；DTS 去掉总线级/per-PHY reset-gpios，把 `phy-reset-gpio`
留给 qca-ssdk。真机 `ls /sys/bus/mdio_bus/devices/` 六个设备齐全。

## 4. 第一次刷机「失联」与恢复（09:xx–10:5x）

同一镜像早上从 24.10 刷入后，主机侧看设备完全失联（网卡 link down、ping 100%、
无 TFTP 回拉），按当时的判断走了恢复流程。事后复盘：**管理网线当时插在 2.5G 口**，
而 24.10/25.12 里 2.5G 都是 WAN 区（`eth1`），管理面在 `eth0`（10G）与
`eth2/eth3`（1G）的 `br-lan` 里。10:5x 同一镜像复刷成功，说明镜像本身没有启动
故障，早上的「失联」是接线位置导致的管理错觉。

恢复过程（供下次参考）：

1. Reset + TFTP 进官方 RAM 系统（SNAPSHOT r38189 / 6.18.60，root 空密码）。
2. RAM 系统上 `sysupgrade -F -n /tmp/v95-1.bin` **静默无效**：没报错，但 p25 头
   仍是 25.12 FIT、p27 只读挂载仍是旧 25.12 根；日志在 tmpfs，已丢失。
3. 改手工 dd（脚本 `~/sbe1v1k-ramtest/flash-v95-1/reflash-v951.sh`）：payload
   sha 预检 → p25 头清 8 扇区 → kernel 写 p25（11505 整扇区 + 364 B 尾扇区，
   分开校验）→ root 写 p27（149760 扇区）→ 整段读回 sha → 分区头魔数。
4. 重启后 v95-1 起，Wi-Fi 自动被主机连回（`192.168.1.230`），用 Wi-Fi 完成
   LuCI/SSH 验证。

## 7. 残留噪声与已知项（不阻塞）

- `qca_ssdk` 加载时 3 次 `__reset_control_get_internal` WARN 调用栈
  （`ssdk_gcc_clock_init`），端口与时钟功能不受影响；
- `insmod qca-nss-sfe.ko` / `ecm.ko` 启动报错：NSS 采用分层显式装载
  （`tier=wired`，默认只装 ssdk+dp，见 `docs/NSS_AUTOLOAD_OFF.md`）。手动验证加载
  顺序为 `qca-nss-ppe-rule` → `qca-nss-sfe` → `ecm`（全部 rc=0，`ecm_dump.sh` 可见
  连接），验证后已 `nss-load stop ecm` 恢复 wired 档位；
- 旧已知项照旧：`qcom_wdt` 取不到输入时钟、edma VP→queue 映射警告、
  `ssdk_uniphy_reset: reset(5) not exist`、radio 启动时 `-95` 提示。
