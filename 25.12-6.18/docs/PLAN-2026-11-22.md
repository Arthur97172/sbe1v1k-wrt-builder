## 2. 网口角色（要求 3，已落地）

上游 `ipq9570-sbe1v1k.dts` 把 port@5（QCA8081，2.5G）标为 `lan1`、port@6
（RTL8261N，10G）标为 `wan`。本树 `patches/0001-...-swap-port5-port6-labels`
交换这两个 label，令：

| DTS 端口 | PHY | label（本树） | 角色 |
|---|---|---|---|
| port@5 | QCA8081（MDIO 28） | `wan` | **2.5G WAN** |
| port@6 | RTL8261N（MDIO 0） | `lan1` | 10G LAN |
| port@3 | QCA8075（MDIO 18） | `lan2` | 1G LAN |
| port@4 | QCA8075（MDIO 19） | `lan3` | 1G LAN |

`02_network` 的 `lan1 lan2 lan3` / `wan` 分组无需改。S3 换成 NSS 数据通路时，
同样的角色映射要在 ssdk 成员表与 UCI 里重建（对应 6.12 的
`no-dsa-ssdk-portvlan-roles` 经验），并用 `verify-image` 的静态断言兜底。

## 4. NSS 移植（S3）的路线

6.12 树的 NSS 不是独立目录，而是「补丁 + 源码装配」：

- `patches/0002–0022`（内核导出面：swconfig、bridge FDB、NAT46、route
  notify、bridge offload、netdev hw_offload 等）；
- `nss/`（qca-ssdk、qca-nss-dp、qca-nss-ppe、qca-nss-ecm、qca-nss-sfe
  等的源码包与 local-packages）；
- `patches/0009/0011`（NSS 的 DTS 数据通路）与 `0024`（内核装载地址）；
- 6.12 上已修过的内核 API 差异：`register_sysctl` 哨兵（0025/0008）、
  eMMC 复位、PCS 时钟父节点（0037）、qca8084 重名（0030）等。

移植到 6.18 的做法（按依赖顺序，不整体搬）：

1. 先搬 `qca-ssdk`（用户态/内核模块 + `ssdk_sh`），只做到编译通过；
2. 再搬 `qca-nss-dp` + `qca-nss-ppe` + `qca-nss-sfe` + `qca-nss-ecm`，
   逐个解决 6.18 内核 API（`register_sysctl`、`netdev_ops`、`phylink`、
   `dev_addr`、时钟/复位框架）差异；
3. DTS 侧按 6.12 的 `0009/0011` 生成 6.18 版 NSS DTS；
4. 每搬一层都本地全量构建 + `verify-image`；真机测试按用户批准逐个里程碑做；
5. 任何组件在 6.18 无法编译/绑定时，如实记录并保留 mainline PPE 兜底。

QSDK 上游对 6.18 没有现成支持（QSDK14 是 6.6），本阶段属于自维护移植，
工作量最大；在 S1/S1b 打通前不启动，避免同时引入两个变量。

## 5. 验证方法

静态：`bash -n`；prepare 断言（6.18 内核、设备定义、eMMC 分支、BDF、DTS、
端口标签）；`fetch-plugins.sh --dry-run`（18 仓库全部 same）；
`check-packages.sh seed/config`（必装/必禁 107 项 PASS）；`verify-image.sh`
（sysupgrade 成员、FIT 本板 DTB、squashfs、`openwrt_release`、apk 数据库按
`required-packages.txt` 逐包反查）。NSS 阶段追加：模块存在性、`nss-load`
档位脚本、DTS 里的 dp/ppe 节点断言。

真机：沿用 6.12 的取证方式（无串口）：`sysupgrade -n`、USB 网卡管理、
启动循环/风扇/灯/LAN DHCP、`/sys/ssdk/packet_counter`、尾部 ext4 三项。
